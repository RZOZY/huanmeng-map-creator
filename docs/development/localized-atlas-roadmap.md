# 分层地图、加载内核与本地汉化实施纲领

状态：2026-10-26，分阶段实施中。单一世界图实验保留，不再把它当作日常精细制图路线。未稳定验收前不推送，不覆盖用户原图。

## 一、完成目标与边界

1. **世界图**只承载国家地缘、广域地区、主要关系与局部图入口，不为村落级细节加载全部高密度模型。
2. **局部图**承载精细地形、聚落、水系、生态与调查地点；世界与局部共用经纬度和稳定地点标识，不共用 cell 下标。
3. 优化要有载入、首帧、交互与内存证据，不以关图层、缩小文件或局部微基准替代端到端验收。
4. 本地可控字幕、菜单、说明、默认生成名称、图例与导出标识须逐项核查。品牌、技术 ID、格式字段、署名和用户原文不盲目翻译；系统界面和外部网页单独列边界。
5. 不因数据“放得下”就认定地图满足设定。地名落水、缺湖、河道与地名错认等属于地图内容缺陷，不能由性能优化自动消除。

## 三、性能证据及其限度

### 3.1 首轮 CPU 定位

同一候选 Electron 的 CDP CPU 采样，旧世界统一图约 250278 个 grid 点、107615 个 packed cell；局部详图约 100014 个 grid 点、79568 个 packed cell。

| 采样阶段 | 世界统一图 | 局部详图 |
|---|---:|---:|
| 到 map:generated 注册事件 | 20.69 s | 13.70 s |
| grid.rebuildGraph | 7.64 s | 3.30 s |
| Pack.generate | 2.91 s | 2.32 s |
| Layers.drawAll（包含下级绘制） | 5.39 s | 2.93 s |
| SVG 注入 | 0.56 s | 0.21 s |

这是**首轮带 CPU profiler 的测量**，不能据单样本宣布平均值、硬件普遍性能或优化收益。嵌套阶段不能相加；GC 在世界采样中约 7.47 s，不是额外叠加到总耗时上的独立阶段。世界 16401 个冰图形的重绘约 0.56 s，不能仅凭其数量认定它是首要瓶颈。

候选窗口处于后台时 requestAnimationFrame 可能不触发。采样必须分别记录模型注册、渲染提交、实际首帧与可交互，不能把超时误报成地图加载失败，也不能把计时器兜底当作已绘制首帧。

后续复测：相同地图、同一构建、同样图层与视窗，各至少 3 次；分别报告冷/暖 median、long task、DOM/path 数据量及可获得的 GC 后保留内存。性能对照期间不得同时构建或运行大量测试；CPU 采样仅用于定位，正式耗时另跑未开启 profiler 的对照。

### 3.2 首批优化的非 CPU 采样对照

相同机器、同一用户数据目录、相同地图/图层；基线为隔离工作树的 `b9357d46` 构建，候选为本轮修复构建。每版本、每地图各 3 次加载。两组均关闭 CPU profiler，但保留同样的阶段计时包装；没有同时运行构建或密集测试。首帧定义为 `map:generated` 后前台连续两次动画帧；两组 6 次均确认前台绘制。以下是各组 median，不是冷启动或不同机器的性能保证。

| 指标 | 世界基线 | 世界候选 | 局部基线 | 局部候选 |
|---|---:|---:|---:|---:|
| 模型注册 | 2098.5 ms | 1748.6 ms | 1127.8 ms | 896.4 ms |
| 首帧就绪 | 2143.2 ms | 1822.1 ms | 1152.3 ms | 947.2 ms |
| grid.rebuildGraph | 634.4 ms | 354.1 ms | 215.4 ms | 136.9 ms |
| Pack.generate | 259.0 ms | 212.2 ms | 192.4 ms | 126.7 ms |

该样本中首帧耗时分别下降约 **15.0% / 17.8%**。世界 Voronoi 两段邻接构造合并、避免逐 cell 临时数组，相关结果由严格差分测试覆盖；不改变浮点计算、邻接顺序、稀疏槽位与 20 步遍历保护。不能把单函数微基准的倍数写成整图加载倍数，也不能拿 3.1 中开启 profiler 的数字计算本表收益。

两组 grid/pack/冰/聚落/自由标签/SVG 节点数量一致：世界 `250278/107615/16401/6/68/19430`，局部 `100014/79568/0/6/42/2009`。这是结构计数核对，不等于全部图数据逐值证明；算法差分、引用修复及旧档往返仍分别验收。现有两个 `.map` 只读加载，未覆盖、未重生成或降精度。

## 四、关联模型：先独立兼容，再接入界面

采用外部、带版本的关联清单，保留每张 `.map` 独立可加载。清单至少具有：

- 项目/世界 UUID，地图 UUID、相对资产位置、地理修订号与来源标记；seed、文件名和数组下标都不是稳定身份。
- 明确投影与完整精度的经纬度 frame、局部图 bounds；坐标转换不使用默认两位舍入。
- 地点稳定 UID、权威经纬度、类型与来源，及每张地图的本地对象绑定。地名可改，UID 不随名字改变；cell、burg、marker ID 仅在本图内有效。
- 局部图覆盖范围、细节级别、父世界与修订基准；重叠时须有确定选择规则，不能默默用最后加载者覆盖。

约束：

1. 等经纬映射必须能正反算；跨 ±180° 使用展开经度，不能将一小块局部图误当近全球覆盖。
2. 元数据 frame 与地图实际地形不符时拒绝自动对齐并说明原因。禁止“吸到最近陆地”后不更新权威记录，亦禁止为了消除警告而默默改地形。
3. 打开局部图只载入该图；返回世界图释放旧模型、还原相应视野。未保存修改必须有取消/保存/放弃的明确选择，默认不丢数据。
4. 世图与局部精度不同是正常的；局部细节不能反向伪装成世界格网已具备的精度。
5. 现有 Submap/resample 会改变地形、气候、聚落、路线和经济，不直接当作无损关联器。先抽纯坐标/裁切功能，逐项验证。
6. 不把自定义 manifest 随意塞进严格解析的 options；没有版本化协议与往返测试前，不改变 `.map` 格式。

## 五、内核与渲染取舍

- 首选低分配、索引化与无输出变化的局部优化。Voronoi 邻接顺序、浮点结果、边界与遍历保护均必须差分一致。
- 载图引用修复不得误改其他字段。无效 culture 只能修 culture，不能清 province；路线查找须正确处理合法 ID 0、空邻接表与稀疏 ID。
- 旧 SVG 不可直接删除：迁移可能依赖其中的标签、冰、浮雕、图层和移动顶点。必须先拆分迁移、场景建立与可见节点物化，再考虑去掉双重构造。
- Worker/二进制缓存/格式升级是后续可选项，不作为掩盖当前同步长任务的口号。只有可取消、可版本失效、不会制造第二套状态真值且测得收益后才接入。
- 异步图层完成与最终视窗协调要纳入载入事务，不能用提前打印的 TOTAL 当作全部资源与首帧完成。
