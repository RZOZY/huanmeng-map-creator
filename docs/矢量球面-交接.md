# 地球仪 · 矢量球面改造（已完成）

> 交接文档。上一轮的结论是「贴图路线无解，必须改成矢量球面」；**现在这一步已经做完并验证过了**。
> 本文记录最终实现、必须遵守的约束、验证方式，以及还没有解决的部分（1.0 的前置项）。

产品：**HuanMeng Map Creator**，当前 **0.6.0**（地球仪问题完全解决前不升 1.0）。

---

## 一、做了什么

地球仪原来是「球面 + 等距圆柱贴图」，有两个数学上躲不掉的问题：

1. **极点收敛**：地图顶边整行在球面上收敛成一个点，极区被挤成放射状花瓣
2. **经线接缝**：地图左右两端内容不同，±180° 一道硬边

现在改成**矢量球面**：不贴图，用地图自己的 Voronoi 单元按顶点经纬度投到球上，逐单元上色。
极点是普通顶点，跨接缝的多边形直接连过去，两个问题一起消失。

| 位置 | 内容 |
|---|---|
| `src/renderers/globe-vector.ts` | **纯计算**：裁剪、投影、取色，产出三角形与顶点色数组（不依赖 three） |
| `src/renderers/globe-vector.test.ts` | 几何与取色的单测（6 个用例） |
| `src/renderers/view-3d-renderer.ts` | `addGlobeVectorMesh()` 把数组塞进 BufferGeometry；`addGlobeBaseSphere()` 区域地图的底球 |
| `tests/e2e/globe-vector.spec.ts` | 浏览器里打开地球仪、旋转、截图，并断言球面圆盘内没有背景色像素 |

开关：`view-3d-renderer.ts` 里的 `USE_VECTOR_GLOBE`。设成 `false` 回到原来的贴图球（贴图路径
`updateGlobeTexure` 完整保留，没有被删）。

## 二、坐标换算（必须遵守）

**铁律：`lonT` / `latT` 是「跨度」不是边界。** 权威定义在
[`src/utils/commonUtils.ts`](../src/utils/commonUtils.ts) 第 250、262 行：
`lon = lonW + (x / graphWidth) * lonT`、`lat = latN - (y / graphHeight) * latT`。

- 默认 `{ latT: 180, latN: 90, latS: -90, lonT: 320, lonW: -160, lonE: 160 }`
- **整世界地图**（`latT > 179`，与 `updateGlobeTexure` 同一判定）经度要**横向拉伸铺满整圈**：
  `lon = -180 + (x / W) * 360` —— 直接套引擎公式只能覆盖 88.9%，两侧各留 20° 空洞
- **区域地图**用引擎自己的真实跨度，不拉伸
- 球面坐标：`phi = (90 - lat) * π/180`，`theta = (lon + 180) * π/180`，
  `p = [-sinφ·cosθ, cosφ, sinφ·sinθ]`（与原来的 `SphereGeometry(1,64,64)` 朝向逐点一致）

## 三、拓扑上必须做的两件事（少一件就会留洞）

1. **边界环外推**：引擎的 `grid.boundary` 只在地图外 `1*spacing`。斜切处会让个别矩形内点的
   最近站点变成边界伪点 —— 离线脚本实测**约 0.023% 的地图矩形面积不属于任何真实单元**，
   投到球上就是极点/边缘的洞（这正是更早那两次失败的原因）。把伪点再外推 1 个 spacing
   （合计 2 个）后重算 `calculateVoronoi`，矩形内每点都严格离真实单元更近，覆盖 100%。
2. **裁到地图矩形**（Sutherland–Hodgman）：把越界顶点压到边上 —— `y=0 → lat=+90`（极冠收成
   一个点）、`x=0 / x=W → lon=∓180`（同一条经线，接缝闭合）。裁剪后各单元并集 = 矩形本身。

另外：引擎的 Voronoi 环**偶尔是反向的**（9975 个里有个别），要按带符号面积统一环绕序，
否则那一格的三角形会全部朝内被剔除 —— 又是一个极点上看得见的洞。

## 四、取色

不要依赖 `gridToPackCellMap`（地球仪路径下是空的），从 `pack.cells.g` 自己建反查表：

```ts
有主陆地 → pack.states[pack.cells.state[packCell]].color
无主陆地 → pack.biomes[pack.cells.biome[packCell]].color
水域     → 生物群系 0（海洋）的颜色，默认 #466eab
```

**色彩空间有坑（实测踩过）**：地球仪走的是 `public/libs/three.min.js`（旧版全局构建，**没有 ColorManagement**），
颜色原样进着色器、输出也不再编码。所以顶点色必须给**原始 sRGB 通道值**（`channel / 255`），
与那个构建里 `new THREE.Color(hex)` 的行为一致。若按现代 three 的习惯预先线性化，整个球会明显偏暗
（海面 `#466eab` 会渲染成 `#102868`）。单测 `hexToColorChannels` 里钉了这条。

两个「看着像 bug 其实正常」的点：

- `pack` 生成时**剔除了深海点**，所以约半数 grid 单元没有 pack 对应——它们全是水，退到海洋色兜底，
  视觉上无缝。**陆地必须 100% 有对应**，否则会出现没上色的灰块。
- 2D 平面图的 state 层是**半透明叠在生物群系/高度图上**的，比球面用的原始 state 色淡得多。
  两者颜色不一致是正常的，不是取色错位。

## 五、怎么验证（改任何一处都重跑）

```powershell
# 几何与取色的单测（不需要浏览器）
node node_modules/vitest/vitest.mjs run src/renderers/globe-vector.test.ts

# 浏览器里打开地球仪、旋转、截图 + 圆盘无背景色像素（本机没装 playwright 浏览器，
# 用系统 Edge；应用启动给的是随机区域地图，所以测试里显式覆盖坐标）
$env:CHROMIUM_PATH='C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe'
node node_modules/@playwright/test/cli.js test tests/e2e/globe-vector.spec.ts --project=chromium
```

单测覆盖的不变量（都是"错了就一定看得见"的量）：

- `Σ 球面三角形实体角 / 4π = 1` —— 有洞会小于 1，有重叠会大于 1
- `Σ 三角形带符号体积 > 0` —— 整体朝向朝外（反了就是看到球的背面）
- 没有法线朝内的三角形；所有顶点都在单位球面上
- 区域地图的经纬度边界精确落在 `lonW/lonE/latS/latN`
- 取色只出现预期的三种颜色（国家色 / 生物群系色 / 海洋色），且 sRGB→线性转换与 three 完全一致

离线辅助脚本（放在工作区，不进仓库）：`verify-sphere-coords.mjs`（坐标数学）、
`analyze-globe-coverage.mjs`（边界外推的依据）、`check-globe-screenshots.py`（截图像素统计）。

## 六、已验证失败、不要再试的方案

| 方案 | 结果 |
|---|---|
| 极区模糊 + 极冠压平 | 极区看不清，否决 |
| 极点补偿小图（方位等距投影） | 太小看不清，放大后仍有花瓣，否决 |
| **Cube Sphere 六面贴图** | 实测**拼接感更强**，六个面之间有明显直线接缝，比单张贴图更差 |
| 换完整世界高度图 | 有效但只修数据层（cn.12） |
| 各向异性过滤 + mipmap | 有效但只改善清晰度（cn.13） |

结论：把一张平面图贴到球上，**极点收敛与经线接缝无法用贴图方式消除**（three.js 官方论坛同一
结论）。矢量球面是唯一根治路线，已经落地。

## 七、还没解决的部分（1.0 的前置项）

1. **区域地图的底球是纯海洋色**。旧贴图版本在区域之外铺的是云纹底图；现在是一层海洋色球
   （`addGlobeBaseSphere`，半径 0.998 防 z-fighting）。想要云纹的话把底球材质换成云纹理即可。
2. **高纬度单元在球面上被压扁**：地图是等距圆柱数据，同样的方格在高纬度对应的经度距离要乘
   `cos(lat)`，所以极区单元会变成细长条。矢量球面不再把它糊成花瓣，但这个畸变来自**地图数据本身**；
   要根治得让生成侧的单元按球面面积分布（这属于生成器改造，不是渲染层能解决的）。
3. **单元边界没有曲线插值**：海岸线与国界就是 Voronoi 多边形的直边。
4. **性能**：每次重建约 80 ms（含一次 Delaunay），切换图层时地球仪会重建一次。
5. **存档格式版本与产品版本已解耦**：`versioning.ts` 里 `VERSION`（产品，0.6.0）与
   `MAP_FORMAT_VERSION`（存档，1.154.0）。改产品版本不要动后者，否则旧存档会被判成
   "来自更新版本"而拒绝加载。
