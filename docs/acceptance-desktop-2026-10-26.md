## 实机发现的缺陷与修复

世界配置重算会更新湖泊分组及河名，但原先仅重绘群系、坐标、河流和冰层，遗漏了湖泊和标签。由此出现“模型已解冻，画面仍是冻湖”的状态；重载或手动重开图层后才恢复。

修复位于[世界配置控制器](<../src/controllers/world-configurator.ts>)：

```ts
Layers.draw("biomes", "coordinates", "rivers", "ice", "lakes", "labels");
```

[对应单测](<../src/controllers/world-configurator.test.ts>)同时约束手动应用与自动更新两条路径。先将断言加入旧实现，得到 2 项预期失败，再补齐重绘，测试转绿。

复测先误用了普通 Web 构建，Electron 仍在使用旧渲染目录。随后执行正式桌面构建并刷新候选窗口，才取得上述修复后结果；不将旧包上的失败算作修复通过。

## 地图侧待修：旧定位参数与显式窗口冲突

此前地图工程直接写入了经纬度窗口，却留下另一套旧生成参数：

```json
{
  "mapSize": 60,
  "latitude": 0,
  "longitude": 0,
  "coordinates": {"latN": 59.3, "latS": 20, "latT": 39.3, "lonW": 78, "lonE": 148, "lonT": 70}
}
```

世界配置面板按前者计算位置，打开面板便把窗口重算为北纬 90°至南纬 18°、西经 12°至东经 180°。因此它不是本轮气候修复引入的错误，而是我此前制图时保存了不一致的定位元数据。

地图工程应另存修正版，使生成参数与窗口保持一致，并核对所有已锁定地名。应用代码不应为了掩盖这个特定地图的元数据冲突而跳过正常的坐标计算。本次只取证，没有覆盖或悄悄修写原图。
